# Rules for agents working on Linework

Linework is a static, browser-only CAD drawing viewer + markup tool (DXF, DWG, DGN v7). Read
README.md first (and DWG.md for the DWG reader). These rules are not optional.

## Hard rules

1. **Clean room.** Never decompile, disassemble, or copy from proprietary CAD software or its
   libraries. Implement formats only from public documentation (the published DXF reference,
   the public ISFF/DGN v7 description) and from permissively licensed open source (GDAL's
   dgnlib is MIT/X — credit anything derived from it in NOTICE). Do not use proprietary product
   names in the product name, UI branding or file names; "opens DXF and DGN v7 files" is fine.
2. **Synthetic fixtures only.** Every test drawing must be generated by a script in `tools/`
   (`make_fixtures.mjs` for DXF, `make_dgn_fixtures.py` for DGN, `make_dwg_fixtures.mjs` for
   DWG — it converts the synthetic DXF files) with invented subjects. Never
   open, copy, render, screenshot, describe or reference a real drawing — in particular nothing
   from anyone's work or client projects. If a bug needs a reproduction, write a new synthetic
   fixture that reproduces the quirk.
3. **Files never leave the device.** No uploads, no analytics, no telemetry, no external
   requests of any kind from the app (no CDNs, fonts, or APIs). `tests/unit/shell.test.mjs`
   enforces "no external URLs" in the app shell. Do not weaken that test.
4. **Vanilla JS, no framework, no build step, no runtime dependencies.** ES modules served as-is.
   `package.json` must not gain `dependencies`. Playwright is used for tests only, loaded from
   `NODE_PATH`, never vendored. The one vendored component is the DWG reader in
   `vendor/libredwg/` (GNU LibreDWG, GPL-3.0-or-later, loaded only when a DWG is opened): change
   it only by building it with `tools/build_dwg_wasm.sh` (the GitHub workflow
   `build-libredwg-wasm.yml` runs it) and installing the build with `tools/vendor_libredwg.mjs`;
   keep its glue free of `eval`/`new Function` (the CSP allows `'wasm-unsafe-eval'` only), and
   bump `READER_REV` (`src/formats/dwg.js`) together with `READER_CACHE` (`sw.js`).
5. **Static only (~$0 to run).** No server code. Anything that needs a server is out of scope.
6. **Tests are required.** Every change must keep `npm test` (Node unit tests) and the
   Playwright e2e suite green, and new behaviour needs new tests. Do not delete or loosen
   assertions to make them pass; fix the code.
7. **No push, deploy, publish or account creation** unless the owner explicitly asks.

## Product principles (the acceptance bar)

Lightweight (startup code — index.html, app.css, the modules src/app.js and the parse worker import
statically — < 150 KB gzipped; everything precached for offline, lazily loaded writers included, < 260 KB; the DWG reader is loaded on demand and cached separately), smooth (60 fps pan/zoom on normal drawings; parsing in
a worker with progress), easy (a first-time user can open, measure and mark up in a minute; few
labelled buttons; undo always available), actually works (robust to real-world quirks; never
crash on a bad file — show what loaded plus "N items not shown"), and cheap (static hosting).

## Map of the code

| Path | What |
|------|------|
| `src/model.js` | Common drawing model shared by all readers. |
| `src/formats/dxf.js`, `dgn.js`, `detect.js` | Readers + format detection (`parseDrawingAsync` for DWG). |
| `src/formats/dwg.js` | DWG reader: loads LibreDWG (WebAssembly) lazily, maps DWG objects to DXF groups read by `readDxf`; fallback via LibreDWG's DXF writer. See DWG.md. |
| `vendor/libredwg/` | LibreDWG WebAssembly + glue (vendored, provenance in its README). |
| `deploy/_headers` | HTTP headers for the static host (CSP with `'wasm-unsafe-eval'`, caching); `tools/serve.mjs` applies it. |
| `src/scene.js` | Model → render scene: block expansion, colours, local origin, spatial grid. |
| `src/view/renderer2d.js` | Canvas2D renderer (interface designed so WebGL can replace it). |
| `src/tools/snap.js`, `measure.js` | Snaps and measurement maths (pure, unit tested). |
| `src/tools/compare.js` | Revision compare (pure): items described from the scene (+ DGN element-byte hashes), matched, paired as moved / changed. |
| `src/markup/*` | Markup model, sidecar format (see MARKUP_FORMAT.md), history, drawing. |
| `src/edit/*` | Edit operations, edit document (changes, undo), live scene updates, clipboard (copy / paste payloads and their conversion between drawings); v0.4 editing tools, pure and unit tested: `find.js` (find / replace text, also in cells), `keyin.js` (XY= DL= DI= AA= key-ins), `xform.js` (mirror, scale, array), `attrs.js` (select same, match attributes, element info), `levels.js` (DGN level-name files). |
| `src/app.js`, `src/app/*` | UI shell, input, tools, export/print. Loaded after start-up / on first use (keep them out of the static graph): `files.js` + `store.js` (file picker handles, Save over the original, recent drawings, IndexedDB journal of unsaved edits), `compare.js` (compare overlay), `print-svg.js` (vector print to scale), and `tools-ui.js` (the editing tools' UI: find bar, key-in preview, More menu, dialogs, info card, level names; imported on first use through `app.loadTools`). Modules hook in through `app.hooks` (`open`, `history`, `draw`). |
| `src/worker.js` | Parse worker. |
| `sw.js` | Offline app-shell cache. **Add new files to `SHELL` (or `ON_DEMAND` if loaded lazily) and bump the version in `src/version.js`** (the one place it lives; the about line, saved files and the cache name read it). The DWG reader has its own cache (`READER_CACHE`). |
| `tools/` | Fixture generators (`dwg-r2000.mjs` = test-only DWG writer), DWG reader vendoring/build, palette extraction, icon rendering, static server, `make_dist.mjs`. |
| `tests/unit/` | `node --test` suites. `tests/e2e/run.mjs` is the Playwright suite. |

## Commands

```
node tools/make_fixtures.mjs           # DXF samples + edge-case fixtures (+ 50k stress, not committed)
python tools/make_dgn_fixtures.py      # DGN fixtures + OGR oracles (needs Python GDAL)
node tools/make_dwg_fixtures.mjs       # DWG R2000 fixtures from the synthetic DXF files
tools/build_dwg_wasm.sh                # build the DWG reader from pinned sources (runs on GitHub Actions, see DWG.md)
node tools/vendor_libredwg.mjs <dir>   # check a reader build (e.g. the CI artifact) and install it into vendor/libredwg/
node tools/make_dist.mjs               # deployable folder in dist/ (incl. _headers)
npm test                               # unit tests
NODE_PATH=<dir with playwright> node tests/e2e/run.mjs   # e2e + screenshots + perf -> tests/e2e/out/
node tools/serve.mjs 8080              # local static server
```

File pickers (`showOpenFilePicker`, `showDirectoryPicker`) cannot be driven headlessly: e2e tests stub
them to return real handles from the origin-private file system (`navigator.storage.getDirectory()`),
and cover the fallback (plain chooser, downloads) by setting `window.showOpenFilePicker = undefined`.
The journal must never hold file contents, only the EditDoc change list (entities as read from the
file are stored as markers); recent drawings hold names, sizes, dates and handles only.

Look at the e2e screenshots after UI changes (dark + paper, 1440/1024/390) and fix anything
that looks wrong before reporting.

## Conventions

* Coordinates: readers emit drawing units; the scene subtracts a local origin (`scene.origin`)
  for float precision; markups and measurements are stored in absolute drawing coordinates.
* Colours: `FG` (ACI 7) means white on dark / black on paper; never hard-code white.
* Keep UI text plain and short, with tooltips and keyboard shortcuts listed in the help sheet.
* Every drawing change goes through the Edit controller's `commit` (one undo step, DGN bytes kept):
  build changes with the pure functions of `src/edit/` (e.g. `setText` / `withPart` for text, never a
  re-encode). DGN level names are display-only (browser storage per drawing name), never written.
* Commit messages end with the `Co-Authored-By` trailer the owner asks for.
